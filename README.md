The Volatility Contraction Pattern (VCP) algorithm in a Mark Minervini–style screener is designed to programmatically detect the tightening price behavior and decreasing supply that precede a institutional breakout.Translating Minervini's discretionary rules into deterministic code involves a systematic, multi-step pipeline combining peak-trough segmentation, progressive amplitude checking, and volume profile analysis.1. High-Level Technical Logic FlowThe algorithm evaluates daily price arrays ($O, H, L, C, V$) to find structures matching a coiling spring:Trend Template Prerequisite: Confirms the stock is in a structural Stage 2 uptrend (Price > 50 EMA > 150 SMA > 200 SMA, with rising slopes) before running pattern math.Swing Peak & Trough Detection: Identifies local swing highs and subsequent pullbacks (troughs) to map distinct contraction waves.Progressive Contraction Constraint: Asserts that each successive pullback is smaller in amplitude than the preceding one (e.g., Wave 1: -25%, Wave 2: -12%, Wave 3: -5%).Volume Dry-Up Validation: Confirms that trading volume shrinks during pullbacks and expands on rallies or near the breakout pivot.2. Mathematical Implementation & Code LogicStep A: Swing Extremum Identification (Peak-to-Trough Mapping)The algorithm iterates through historical price bars to find local peaks (swing highs where price is higher than $N$ bars left and right) and the subsequent local troughs.Let a contraction wave $W_i$ be defined by a peak price $P_i$ and its corresponding subsequent trough price $T_i$.Depth Percentage Calculation:$$D_i = \frac{P_i - T_i}{P_i} \times 100$$Step B: The Monotonic Decreasing Rule (Contraction Constraint)For a valid VCP with $k$ contractions (typically 2 to 4 waves), the algorithm enforces a strictly decreasing sequence of depths:$$D_1 > D_2 > D_3 > \dots > D_k$$Additionally, the code frequently checks a contraction ratio threshold ($R$):$$R = \frac{D_{i+1}}{D_i}$$Minervini notes that each contraction is roughly half the depth of the prior one ($R \approx 0.4 \text{ to } 0.6$). Code implementations typically flag a valid contraction if $R \le 0.75$, ensuring the volatility is indeed compressing.Step C: The Final Tightness (Low Volatility) CheckThe final contraction ($W_k$, often acting as the "handle" or final consolidation base) must be exceptionally tight, indicating supply exhaustion.Daily Range Tightness:$$\text{Daily Range}_j = \frac{H_j - L_j}{C_j} \times 100$$The algorithm loops through the final 5 to 10 bars of the base to verify that multiple consecutive days show tight ranges (e.g., $\le 1.5\%$ to $2.0\%$ daily spread) and narrow closing changes.Step D: Volume Profile AnalysisPrice contraction without volume confirmation is prone to failure. The algorithm applies two core volume filters:Pullback Volume Dry-Up: During the downward leg of contraction $W_i$, average volume must fall below a moving average baseline (e.g., Volume < 50-day Volume SMA).$$\bar{V}_{\text{pullback}} < \bar{V}_{\text{baseline}}$$Breakout Volume Surge: As price pushes past the pivot point ($P_{\text{pivot}}$—the absolute high of the final contraction), volume must surge relative to average volume:$$V_{\text{breakout}} \ge \bar{V}_{50} \times 1.40 \quad (+40\% \text{ or higher})$$Summary Table of Core Rules in CodeRule ComponentMathematical ConditionCode Verification LogicStage 2 Trend$P > EMA_{50} > SMA_{150} > SMA_{200}$Validates structural macro trend before scanningContraction Decay$D_{i+1} < D_i$Asserts each pullback is shallower than the lastContraction Ratio$0.3 \le \frac{D_{i+1}}{D_i} \le 0.75$Ensures proper geometric tighteningFinal Tightness$\max(H_j - L_j) \le \text{Threshold}$Confirms lack of volatility in final base barsVolume Dry-Up$\sum V_{\text{pullback}} < \sum V_{\text{baseline}}$
In quantitative breakout screeners following Mark Minervini's philosophy, adaptive Average True Range (ATR) multipliers are used to dynamically compute stop losses based on how tight a Volatility Contraction Pattern (VCP) has become.While static stop-loss models use a fixed percentage (e.g., 7% or 8% below entry), an adaptive ATR system scales risk dynamically relative to market volatility and base structure. Here is how the source code implements this logic mathematically and programmatically:1. The Core Adaptive ConceptAs a stock progresses through a VCP from early wide waves ($W_1$) to the final tight handle ($W_k$), its daily range and ATR naturally shrink.Loose Base: High volatility $\rightarrow$ wider ATR $\rightarrow$ needs a larger multiplier to avoid getting stopped out by routine noise.Tight Base (VCP Handle): Low volatility $\rightarrow$ compressed ATR $\rightarrow$ allows a tighter multiplier (closer stop) because the stock is coiling tightly near the breakout pivot.2. Mathematical ImplementationStep A: Calculating the Baseline ATRThe codebase first computes the standard $N$-period ATR (typically a 14-day or 22-day window to capture short-to-medium term fluctuations):$$\text{TR}_i = \max \left( H_i - L_i, \vert{}H_i - C_{i-1}\vert{}, \vert{}L_i - C_{i-1}\vert{} \right)$$$$\text{ATR}_N = \frac{1}{N} \sum_{j=0}^{N-1} \text{TR}_{i-j}$$Step B: Quantifying VCP Tightness (The Contraction Factor)To make the ATR multiplier adaptive rather than static, the code calculates a tightness coefficient based on the depth and duration of the final contraction leg:$$\text{Tightness Index } (\tau) = \frac{D_k}{D_1}$$Where $D_1$ is the depth of the initial pullback wave and $D_k$ is the depth of the final consolidation handle.As the pattern matures, $\tau$ approaches 0 (e.g., contracting from an initial 20% drop down to a tight 3% handle).Step C: Dynamic Multiplier ScalingThe adaptive multiplier ($\text{AM}$) scales inverse-linearly or via a scaling function tied directly to $\tau$ and daily range compression:$$\text{AM} = \text{Base Multiplier} \times \left( 1 + w \cdot (1 - \tau) \right)$$Alternatively, in simplified programmatic implementations, the code checks the final base daily range or ATR percentage relative to price ($ATR\% = \frac{\text{ATR}_N}{\text{Close}} \times 100$):If $ATR\%$ is very low (indicating extreme tightness), a lower multiplier (e.g., $1.0\times \text{to } 1.2\times \text{ATR}$) is applied.If volatility is still expanding or loose, the multiplier scales up (e.g., $1.5\times \text{to } 2.0\times \text{ATR}$) to accommodate normal volatility.3. Programmatic Stop-Loss & Position Sizing OutputOnce the adaptive multiplier is resolved, the final stop-loss price ($S$) and position sizing variables are computed as follows:Stop-Loss Price Level:$$S = \text{Pivot Price} - (\text{AM} \times \text{ATR}_N)$$(The code will often choose the higher value between this ATR-derived stop and the actual structural swing-low of the final VCP trough to ensure logical technical placement).Risk-Adjusted Position Sizing:
The calculated risk per share ($\text{Risk}_{\text{share}} = \text{Entry Price} - S$) is fed into the portfolio risk model:$$\text{Shares to Buy} = \frac{\text{Total Capital} \times \text{Risk Allocation \%}}{\text{Risk}_{\text{share}}}$$
